# Kind dispatch

Spec. Graduates into [[architecture/modules]], [[mechanics/machines]], [[mechanics/sensors]], [[architecture/view]], [[architecture/save]]. No save change. No player-visible change.

Follows the `BaseBuilding` / `Machine` / `Store` pass — [[architecture/modules]] Building I/O. That pass moved `accept` / `apply` / `ports` / `pads` / `takeAll` onto the class and collapsed three `dest.kind` chains. This one finishes the job for the chains it did not reach.

## Census

`kind === '<building>'` in `src/game`, tests excluded: **268 comparisons**. Grouped by *why* the check is made, not by which kind is named.

| why | comparisons | shape | worst files |
|---|---|---|---|
| **membership** — is this cell one of a set | 117 | `a \|\| b \|\| c …` | `overlay.ts` 17, `sensor.ts` 14, `props.ts` 14, `save.ts` 12, `plot.ts` 10 |
| **dispatch** — run different logic per kind | 97 | `if (kind) { … }` blocks | `vehicle.ts` 14, `look.ts` 12, `machines.tick.ts` 11, `prompt.ts` 9 |
| **lookup** — kind names a constant | 54 | `if (kind) return X` | `svgs.ts` 10, `recipe.ts` 9, `hit.ts` 9, `prompt.ts` 8 |

## Three cuts

Ordered by return over risk. Cut 1 is free, Cut 2 is the one that keeps paying, Cut 3 is a correctness fix.

### Cut 1 — Ask the fields that already exist

Six of the thirteen are already answerable from `ports` / `pads`. Nobody deleted the hand-written lists after those fields landed, so the class and the chain are now two sources for one fact.

| site | replace with |
|---|---|
| `hit.ts:205` `portsOf` | `c.ports` — **delete the function** |
| `hit.ts:262`, `overlay.ts:188` | `c.ports.includes('out')` |
| `sensor.ts:256` `portDevice` | `isSensor(c) \|\| c.ports.length > 0` |
| `sensor.ts:618` | `c.ports.includes('in')` |
| `mp.ts:352` | `c.ports.includes('out')` |
| `vehicle.ts:567` | `c.pads === 'both'` |

`hit.ts:205` is the sharp one. It recomputes `mill|jam|still|station → ['in']`, `furnace → ['in','out']`, `chest|freezer|seed-silo|additive-store → ['out']` — which is exactly what `BaseBuilding.ports` holds. Two declarations of one truth, already free to drift.

`hit.ts:262` and `overlay.ts:188` are the same predicate twice, character for character.

Sensors are not `BaseBuilding` and carry no `ports` field. Give the sensor classes the same readonly `ports` so the four sensor-touching sites read one field for both — [[mechanics/sensors]].

No new API. ~40 comparisons gone.

### Cut 2 — Three flags on `BaseBuilding`

Same shape as `pads` / `takeAll`: a readonly field with a default, overridden only where it differs. A new building that wants the default writes nothing.

```
BaseBuilding
  solid  = true      blocks walking
  ticks  = false     belongs in World.machines
  hasted = false     furnace haste applies to its rate
```

| flag | true on | kills |
|---|---|---|
| `solid` | every `BaseBuilding` | the building half of `plot.ts:117` |
| `ticks` | mill jam still grinder barrel furnace station compost-box | `world.ts:750` |
| `hasted` | mill jam still grinder furnace compost-box | `look.ts:197` |

`ticks` and `hasted` differ by exactly `station` and `barrel`, and that difference is real: the station runs on `dt / STATION_SECONDS` with no multiplier, and the barrel ages rather than works — [[mechanics/family]] `machinery`. Today that rule is spelled out once in `family.md` and re-derived by hand in two lists that a reader must diff to notice. Named flags make the difference visible at the class.

Keep `isIoCell` as its own predicate, not a flag alias: it includes `grinder` where `pads === 'both'` excludes it, and that is deliberate — [[architecture/modules]].

`plot.ts:117` keeps its non-building arms (`house` `rock` `tree` `truck` `pump` sensors). Only the `BaseBuilding` arms collapse.

`save.ts:185` / `overlay.ts:117` (question 2) is `c instanceof BaseBuilding` — no flag needed once the class is the test.

### Cut 3 — `tick(w, at, dt)` on `Machine`

`tickMachines` is a 140-line `if (c.kind === …)` ladder over eight machines. It grows by one arm per machine, and each arm re-states the same three preamble lines.

```
Machine
  ticks = true
  tick(w: World, at: Coord, dt: number): boolean
```

Returns whether it changed anything, so the caller keeps its one `dirty` flag.

```ts
for (const at of w.machines.values()) {
  const c = w.cell(at)
  if (!c.ticks || c.base.col !== at.col || c.base.row !== at.row) continue
  if (c.tick(w, at, dt)) dirty = true
}
```

The origin-cell guard and the `ticks` test move to the loop, so each machine body starts at its own first real line. Each machine then owns its own rate, which is where the `machineMul` asymmetry becomes readable instead of archaeological: mill / jam / grinder multiply by `w.machineMul()`, still / furnace / station do not.

`emitProduct` / `emitPair` / `dropSpot` / `pullStillWater` stay free functions in `machines.tick.ts`; the machine calls them. `furnaceSnap` stays on `World` and reaches the machine through `w`.

This is the chain that grows every time a machine is added. It is worth more than its 11 comparisons suggest.

## Not moving

Naming what stays is half the spec.

| chain | stays because |
|---|---|
| `look.ts:127`, `prompt.ts:556` | player copy. `look.ts` and `prompt.ts` are the i18n boundary — [[architecture/i18n]]. A `lookLine()` on `Mill` puts `m.*` inside `sim` |
| `svgs.ts:382`, `props.ts:58`, `vfx.ts` | art. `sim` must not import `view` — [[architecture/modules]]. If the repetition bites, it is a `Record<kind, art>` in `view`, not a field on the class |
| `save.ts` / `save.parse.ts` cell arms | the save is a wire format. A class that writes its own shape couples the format to the code — [[architecture/save]] |
| `place.helpers.ts:98`, `:391` | delete and refund are placement rules over a wider union than `BaseBuilding` (tiles, pipes, fence) |
| `recipe.ts` | `MachineId` rows, not cells |

That leaves the lookup bucket (54) and most of the dispatch bucket (97) deliberately alone. The 268 does not go to zero and should not.

## Order

1. Cut 1 — pure deletion, no new API, no behaviour change.
2. Cut 2 — three flags, mechanical.
3. Cut 3 — one method, one machine at a time; the ladder shrinks by an arm per step and stays green throughout.

Reachable after all three: ~90 of 268. The rest is copy, art, and the save format, which are correctly kind-shaped.

## Invariants

`building.flags` — `BaseBuilding` carries `solid` `ticks` `hasted` beside `ports` `pads` `takeAll`. A building that wants the default declares nothing. No call site re-derives a flag by listing kinds.

`building.ports-single` — `ports` is the only statement of which ports a cell has. `hit.ts` has no `portsOf`. Sensors carry the same field.

`machines.tick-self` — `tickMachines` does not name a machine kind. Origin-cell guard and `ticks` live in the loop; rate and product live on the machine.

Assumption: `hasted` is a flag, not `machineMul` on the class — the still and furnace take furnace haste but not the machinery skill, and one boolean says that where a rate method would hide it.

Assumption: sensors gain `ports` in Cut 1. They are not `BaseBuilding` and this spec does not make them one.
